Cameras

One prop layout can be shot from several camera positions. + Add Camera Position is in the header; add one per shot and name it for the shot it covers ("Wide", "Interview 2") — the name is what labels it on the exported floor plan and in the Disguise CSV, so it's worth typing something the crew will recognise. Every camera position here belongs to the position selected above, and they all carry over when you add a new position. Hide takes a camera off the canvas when several of them overlap into a mess — it stays in this list, stays editable, and every export (floor PNG, CSV, report) still draws it, so hiding never leaves a camera out of the plan.

Live Tracking

How tracking and calibration work

Requires server.py running (see requirements.txt) -- the browser can't reach Motive on its own. Assign each incoming rigid body below to a camera or prop to drive its position/rotation live. Each row has its own axis/rotation/height calibration underneath it — every Motive asset has its own local frame, so these don't share one global value. For a known tracker just pick it from apply profile… (Camera Tracker and T-bar are already calibrated); rows arrive named by number rather than by asset, so that pick can't happen automatically. Otherwise get the axis right first: if it's wrong, rotation jitters and tilt sits near ±90° with the object level, and no offset can fix that. "rot°" is a day-to-day adjustment ON TOP of that row's already-calibrated baseline — it defaults to 0, and 0 means "trust the calibration." Re-placing a tracker by hand naturally reads a few degrees different each time; only change this for a real, repeated discrepancy, not a one-off reading. "h(m)" only matters for a row driving a camera.

GitHub Sync

Saves the setup you're in, then backs up every setup on this machine the repo hasn't already got the latest version of — so one press at the end of the day covers everything you worked on, not just what's open. Each goes up as one JSON file (setups/<id>.json, all its positions, props and frame grabs, overwritten each time) via GitHub's API; setups unchanged since their last backup are skipped. The token is stored only in this browser — use a fine-grained token scoped to just that one repo with Contents: read/write.

Movement Recording

Records this camera's live movement as a path on the floor plan, with its start and end position marked. Assign it to a rigid body in Live Tracking first, then press Record and perform the move. Only movement is kept — time the camera spends parked adds no points, so you can start recording, take your time, and stop afterwards without padding the path. If the camera never moves, the recording saves its tracked position as a static camera position instead, replacing any path it had before.
