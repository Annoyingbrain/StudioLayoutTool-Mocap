Help

Shoot days

The studio and the positions stay put across days; the props and camera positions belong to a day. A new day copies the props where they currently stand — the set is usually yesterday's with things moved — but starts its camera positions fresh, since those get re-rigged. Once copied they're separate: moving a prop today does not touch a day already shot. The lists, the canvas and every export (floor PNG, CSV, report) show the day selected here, and its name goes into the exported filename so one day never overwrites another. Deleting a day deletes its props and camera positions in every position.

Positions

Each position has its own props, per shoot day. Frame grabs hang off the camera positions in the Cameras list, one each — a layout shot wide and then tight is two different reference pictures.

Camera positions

One prop layout can be shot from several camera positions. + Add Camera Position is in the header; add one per shot and name it for the shot it covers ("Wide", "Interview 2") — the name is what labels it on the exported floor plan and in the Disguise CSV, so it's worth typing something the crew will recognise. Every camera position belongs to the position and the shoot day selected in the left panel, and they all carry over when you add a new position (a new day starts fresh instead). Hide takes a camera off the canvas when several of them overlap into a mess — it stays in this list, stays editable, and every export (floor PNG, CSV, report) still draws it, so hiding never leaves a camera out of the plan.

Props

Hide a prop to take it out of the shot without deleting it — it comes off the canvas and out of the floor PNG, the CSV and the report, but keeps its row, stays editable and can still be measured with a tracker. Hiding is per shoot day and per position, so hiding the sofa today leaves yesterday's plan as it was shot. (Hiding a camera position is different: that one only declutters the canvas, and every export still draws it.)

Live tracking and calibration

Requires server.py running (see requirements.txt) -- the browser can't reach Motive on its own. Assign each incoming rigid body in the Live Tracking panel to a camera or prop to drive its position/rotation live. Each row there has its own axis/rotation/height calibration underneath it — every Motive asset has its own local frame, so these don't share one global value. For a known tracker just pick it from apply profile… (Camera Tracker and T-bar are already calibrated); rows arrive named by number rather than by asset, so that pick can't happen automatically. Otherwise get the axis right first: if it's wrong, rotation jitters and tilt sits near ±90° with the object level, and no offset can fix that. "rot°" is a day-to-day adjustment ON TOP of that row's already-calibrated baseline — it defaults to 0, and 0 means "trust the calibration." Re-placing a tracker by hand naturally reads a few degrees different each time; only change this for a real, repeated discrepancy, not a one-off reading. "h(m)" only matters for a row driving a camera.

Camera height and tilt

Height and tilt come from live tracking (Motive's up-axis and the rigid body's orientation) — they can't be typed in. Tilt shares the same uncalibrated forward-axis assumption as Rotation.

Recording a camera move

Records this camera's live movement as a path on the floor plan, with its start and end position marked. Assign it to a rigid body in Live Tracking first, then press Record and perform the move. Only movement is kept — time the camera spends parked adds no points, so you can start recording, take your time, and stop afterwards without padding the path. If the camera never moves, the recording saves its tracked position as a static camera position instead, replacing any path it had before.

GitHub backup

Saves the setup you're in, then backs up every setup on this machine the repo hasn't already got the latest version of — so one press at the end of the day covers everything you worked on, not just what's open. Each goes up as one JSON file (setups/<id>.json, all its positions, props and frame grabs, overwritten each time) via GitHub's API; setups unchanged since their last backup are skipped. The token is stored only in this browser — use a fine-grained token scoped to just that one repo with Contents: read/write.
